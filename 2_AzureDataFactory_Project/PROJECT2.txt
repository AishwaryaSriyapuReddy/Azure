when to use web activity and copy activity to get data from  api?
| Requirement                       | Activity      |
| --------------------------------- | ------------- |
| Copy API data to storage/database | Copy Activity |
| Trigger an API action             | Web Activity  |
| Get OAuth token                   | Web Activity  |
| Read large datasets from REST API | Copy Activity |
| Handle pagination automatically   | Copy Activity |
| Call a webhook/service endpoint   | Web Activity  |

Use Copy Activity when the goal is to extract data from a REST API and load it into a target store such as ADLS, Blob Storage, or SQL Database. Use Web Activity when you need to invoke an API for an action, such as obtaining an access token, triggering a process, calling a webhook, or interacting with a service where data movement is not the primary objective.


Web Activity returns whatever the API sends. Most modern REST APIs return JSON, which ADF exposes in the output.body property. If the API returns XML or plain text, ADF stores it as a string in the response body. Web Activity is best for control-flow operations and small responses, while Copy Activity is preferred for ingesting large volumes of API data.

-->how do you use multithreads and how do you use parallelism in pyspark?

In PySpark, parallelism is achieved through distributed processing across cluster executors, where data is divided into partitions and processed in parallel using Spark’s DAG scheduler and task execution model. We control parallelism using partitions, repartition, and shuffle operations. Python multithreading, on the other hand, runs only on the driver node and is mainly used for I/O-bound operations like API calls or file handling, since it does not provide true distributed parallelism due to Python’s GIL. Therefore, Spark parallelism is used for large-scale data processing, while multithreading is used for auxiliary non-distributed tasks.

-->9.	What is broadcast in Spark? Why is broadcast more efficient? When did you use broadcast?
Broadcast in Spark is a mechanism to send a small dataset to all worker nodes (executors) so that it is locally available during joins or computations, instead of shuffling large data across the network.

✔ Avoids shuffle phase (most expensive part of Spark)
✔ Reduces network I/O
✔ Reduces disk spill
✔ Local in-memory join

When should you use Broadcast?
✔ Best scenarios:
Small dimension tables
Lookup/reference tables
Code tables (country, region, status)
Less than ~10–100 MB (rule of thumb)
